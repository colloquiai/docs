---
title: "Variables"
description: "Values the agent knows about the call, and values it extracts."
---

A variable is a named value available for the rest of the call. Refer to one in any instruction, condition, message or tool field by wrapping its name in double curly braces.

## Built-in variables

These are set when the call starts.

| Variable | Value |
|---|---|
| `user_number` | The caller's phone number |
| `agent_number` | The number the caller dialled |
| `call_id` | The call's id, matching Call History |
| `direction` | `inbound` or `outbound` |

Because the caller's number is already known, never ask for it. Ask whether the number they are calling from is the best one to reach them on.

## Time variables

When the agent has a timezone set, the current date and time are added to every turn, along with a calendar for this week and next so relative dates resolve correctly. You can also use `current_time` and `current_hour` directly, or a specific zone such as `current_hour_Australia/Sydney`. The hour is what you compare against in an hours check, so make sure the variable you compare is numeric.

## Extracted variables

[Extract Variable](/build-an-agent/tools/extract-dynamic-variable) nodes and tools create variables from the conversation. Their type is set when you define them, and that type matters: a number compares numerically, a string compares as text, and an enum is always one of its choices.

## Response variables

A [Custom Function](/build-an-agent/tools/custom-function) can save fields from the API response as variables by JSON path. These are what you branch on after the call.

## Variables in static text

Static instructions and SMS content substitute variables literally. Two things follow:

- A variable that was never set is spoken or sent as its placeholder text. Make sure every path into a node sets the variables that node uses, or branch on `exists` first.
- A phone number is read as one long number unless stored as spaced digits. Have the extraction description produce "0 4 1 2" style output for anything that will be read back.

## Variables the extractor cannot see

The extractor works on recent conversation, roughly the last dozen messages, not the whole call. Extract soon after the value is spoken, and if a value from earlier is needed later, have the agent restate it once so it is back in view.
